# CONTEXTE

Je développe une application Next.js 15 avec l’App Router, TypeScript et Prisma ORM (PostgreSQL).  
L’architecture est pensée pour gérer un système de gestion de projets Agile basé sur le schéma Prisma suivant :  
[INSÉRER ICI LE CONTENU DU FICHIER schema-projec-manager.txt]

Hiérarchie des entités principales :
- Project
  - Initiative
    - Epic
      - Feature
        - UserStory
          - Task
- Sprint (lié à Project et UserStory/Task)
- File (lié à Project, Feature, UserStory, Task, Sprint)

## ARCHITECTURE FRONTEND

- Chaque type d’entité (Project, Initiative, Epic, Feature, UserStory, Task, Sprint, File) a :
  - Une page liste (`/entity/page.tsx`) → Server Component qui récupère les données directement depuis Prisma
  - Un composant Client pour gérer filtre, tri, affichage (`EntityPage.tsx`)
  - Des vues réutilisables : ListView, CardView, TreeView
  - Une barre d’outils (`Toolbar.tsx`) : filtre + tri + choix vue + bouton ajouter
  - Des boutons d’actions rapides (`ItemActions.tsx`) : Edit, Delete, MoveUp, MoveDown
  - Un formulaire (`EntityForm.tsx`) pour créer / éditer
  - Des Server Actions (`/app/actions/entity/*.ts`) : create, update, delete, reorder

- **Réutilisation maximale** :
  - `Toolbar.tsx` est commun à tous
  - `ItemActions.tsx` est commun à tous
  - `ListView.tsx`, `CardView.tsx`, `TreeView.tsx` reçoivent `items` et les mêmes handlers
  - Les Server Actions ne font que de la logique CRUD simple via Prisma

## OBJECTIF

Générer **pour chaque entité** (Project, Initiative, Epic, Feature, UserStory, Task, Sprint, File) :
1. **page.tsx** (Server Component)  
   - Récupère les données depuis Prisma (`db.entity.findMany(...)`)
   - Passe à un composant Client `EntityPage` avec `initialItems`

2. **EntityPage.tsx** (Client Component)  
   - Gère `filter`, `viewMode`
   - Applique le filtrage / tri
   - Rends `Toolbar` et la vue choisie (`ListView`, `CardView`, `TreeView`)
   - Passe les bons handlers CRUD aux vues

3. **Formulaire `EntityForm.tsx`**  
   - Mode ajout / édition
   - Appelle la Server Action `createEntity` ou `updateEntity`

4. **Server Actions (`create.ts`, `update.ts`, `delete.ts`, `reorder.ts`)**  
   - Fonctions simples Prisma (ex: `await db.entity.update(...)`)

5. **Réutilisation des composants communs**  
   - `Toolbar.tsx`, `ItemActions.tsx`, `ListView.tsx`, `CardView.tsx`, `TreeView.tsx` déjà présents

## ATTENTES POUR CHAQUE SCRIPT

- **Langage** : TypeScript
- **Framework** : Next.js 15 App Router
- **Style** : Tailwind CSS + shadcn/ui + lucide-react
- **Type-safety** : utiliser les types générés par Prisma
- **Server Components** : pour le chargement initial des données
- **Client Components** : uniquement pour la gestion UI (filtre, vue, actions)
- **Server Actions** : marquées `"use server"`, pas d’API routes
- **Lisibilité** : code clair, structuré, commenté

Pour chaque entité `Entity` :
- `/app/entity/page.tsx`

- `/app/actions/entity/create.ts`
- `/app/actions/entity/update.ts`
- `/app/actions/entity/delete.ts`
